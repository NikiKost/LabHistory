# LabHistory — «Мои анализы»

Android-приложение на Java для личного учёта лабораторных анализов. Проект рассчитан на несколько локальных профилей: свой, друга или родственника.

## Что уже работает в каркасе

- создание нескольких профилей;
- локальная база Room;
- ручное добавление показателя, значения, единицы и референса;
- выбор PDF или изображения через системное окно Android;
- приём PDF/изображения через меню «Поделиться» другого приложения;
- копирование документа во внутреннее хранилище приложения;
- список документов по выбранному профилю;
- определение ИНВИТРО или Lab4U по имени файла;
- заготовки отдельных парсеров для ИНВИТРО и Lab4U.

OCR и извлечение таблиц из PDF пока не реализованы. Импортированный документ получает статус «Сохранён, ожидает распознавания». Это сделано намеренно: результат нельзя считать распознанным, пока приложение не умеет показать пользователю экран проверки каждого поля.

## Как приложение работает

1. При первом запуске Room создаёт базу `lab_history.db` и профиль «Я».
2. Пользователь выбирает профиль или создаёт новый.
3. При ручном вводе приложение сохраняет документ типа `MANUAL` и связанную с ним запись результата.
4. При импорте Android выдаёт приложению временный доступ к выбранному файлу.
5. Приложение немедленно копирует файл в собственную закрытую папку `analysis_documents`.
6. В базе сохраняются лаборатория, дата, тип источника, исходное имя файла, внутренний путь и статус обработки.
7. Список на главном экране обновляется автоматически через Room `LiveData`.

Приложение не запрашивает общий доступ ко всем файлам смартфона. Выбор производится системным механизмом Storage Access Framework.

## Как работает APK

APK — устанавливаемый пакет Android. В нём находятся скомпилированный Java-код, XML-интерфейс, ресурсы и манифест приложения.

После установки Android создаёт для пакета `ru.labhistory.app` отдельную изолированную область. База и загруженные документы не видны обычным файловым менеджерам и другим приложениям. При удалении приложения локальные данные также удаляются. Облачное резервное копирование базы и медицинских документов в каркасе отключено.

Debug APK автоматически подписывается отладочным ключом компьютера и подходит для установки на свои устройства. Для публикации нужен release APK или Android App Bundle, подписанный постоянным приватным ключом владельца проекта.

## Обновления через GitHub

Release-версия проверяет публичный файл `update.json` из последнего GitHub Release. Если `versionCode` больше установленного, приложение показывает описание, загружает APK через системный DownloadManager, проверяет SHA-256 и передаёт файл системному установщику Android. Пользователь всегда подтверждает установку.

Публикация запускается тегом, совпадающим с `versionName`, например:

```powershell
git tag v0.2.0
git push origin v0.2.0
```

Workflow `.github/workflows/release.yml` требует GitHub Secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` и `ANDROID_KEY_PASSWORD`.

## Сборка

Требования:

- Android Studio с Android SDK 36;
- JDK 17 или совместимая версия;
- подключение к интернету при первой синхронизации зависимостей.

В Android Studio откройте корень проекта, дождитесь Gradle Sync и выберите **Build → Build APK(s)**.

Из терминала Windows:

```powershell
.\gradlew.bat assembleDebug
```

Получившийся файл:

```text
app/build/outputs/apk/debug/app-debug.apk
```

Установка через ADB:

```powershell
adb install -r app/build/outputs/apk/debug/app-debug.apk
```
