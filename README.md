# LabHistory — «Мои анализы»

Android-приложение на Java для личного учёта лабораторных анализов. Проект рассчитан на несколько локальных профилей: свой, друга или родственника.

## Что уже работает

- создание нескольких профилей с необязательными датой рождения и полом;
- редактирование имени и данных профиля, безопасное удаление профиля вместе с его локальными документами;
- локальная база Room;
- ручное добавление показателя, значения, единицы и референса;
- выбор PDF или изображения через системное окно Android;
- приём PDF/изображения через меню «Поделиться» другого приложения;
- копирование документа во внутреннее хранилище приложения;
- список документов по выбранному профилю;
- группировка документов по дате сдачи и поиск по лаборатории, имени файла, типу или статусу;
- отдельный экран документа с предпросмотром фото или первой страницы PDF;
- открытие оригинального файла через системное приложение;
- полностью локальное OCR фотографий и PDF на русском и английском языках;
- чтение встроенного текстового слоя электронных PDF без OCR с сохранением колонок таблицы;
- автоматический переход к OCR, если PDF является сканом или текстовая таблица не распознана;
- подготовка фото перед OCR: поиск листа, обрезка фона, повышение разрешения и адаптивный контраст;
- редактирование и сохранение проверенного распознанного текста;
- разбор OCR-текста в редактируемые строки «показатель / значение / единица / референс»;
- подтверждение строк пользователем перед добавлением в историю;
- автоматическое извлечение даты сдачи/исследования из подписанных полей PDF и фотографий;
- ручное изменение даты сдачи с защитой от перезаписи при повторной обработке;
- словарь сокращений и полных названий показателей: например, АЛТ и аланинаминотрансфераза объединяются;
- группировка одинаковых показателей из разных файлов и график числовых значений по датам сдачи;
- поиск показателей по названию и единице измерения, сортировка по названию, дате или отклонениям;
- быстрый фильтр показателей, у которых последнее значение выше или ниже референса последнего бланка;
- сводка выбранного профиля на главном экране: всего показателей, вне референса и без распознанного диапазона;
- ручное исправление или объединение групп показателей без изменения исходного документа;
- редактирование отдельного измерения с возможностью разделить ошибочно объединённую историю;
- удаление отдельного ошибочного измерения без удаления исходного документа;
- фильтрация графика по периоду сдачи и лаборатории;
- отметка значений выше или ниже референса, указанного в конкретном бланке;
- защита от повторной загрузки одинакового файла в один профиль по SHA-256;
- определение ИНВИТРО или Lab4U по имени файла и распознанному тексту;
- удаление документа, исходного файла и связанных результатов после подтверждения;
- светлая и тёмная темы с корректными отступами от системных панелей;
- обновление APK через GitHub Releases с проверкой SHA-256;
- создание и восстановление переносимой резервной копии `.labbackup`, защищённой паролем и AES-256-GCM;
- контроль свежести резервной копии по числу документов и автоматическое напоминание после изменений;
- перенос профилей, оригинальных PDF/фото, OCR-текста и подтверждённых показателей без облака;
- пропуск уже существующих документов по SHA-256 при повторном восстановлении;
- экспорт показателей выбранного профиля в совместимый с Excel CSV с датой, лабораторией, референсом и статусом;
- опциональная блокировка всех экранов отпечатком, лицом или системным кодом устройства;
- скрытие медицинских данных в недавних приложениях и запрет скриншотов, когда защита включена;
- заготовки отдельных парсеров для ИНВИТРО и Lab4U.

OCR предлагает черновик структурированных строк, но не сохраняет их автоматически. Пользователь сверяет название, значение, единицу и референс с оригиналом. Только подтверждённые числовые значения появляются в истории и на графиках.

## Как приложение работает

1. При первом запуске Room создаёт базу `lab_history.db` и профиль «Я».
2. Пользователь выбирает профиль или создаёт новый.
3. При ручном вводе приложение сохраняет документ типа `MANUAL` и связанную с ним запись результата.
4. При импорте Android выдаёт приложению временный доступ к выбранному файлу.
5. Приложение немедленно копирует файл в собственную закрытую папку `analysis_documents`.
6. Для электронного PDF приложение сначала локально читает текстовый слой и координаты колонок. Если текста нет, страницы распознаются через Tesseract. В облако файл не отправляется.
7. Извлечённый текст сохраняется в Room и доступен для проверки и исправления рядом с оригиналом.
8. Экран проверки предлагает разделить текст на показатели; результат сохраняется только после подтверждения.
9. При обработке приложение ищет подписанную дату взятия материала, сдачи или исследования. Если подходящего поля нет, остаётся дата загрузки, которую можно исправить вручную.
10. Подтверждённому показателю присваивается канонический ключ. Сокращение и полное название объединяются в историю при совпадающей единице измерения.
11. В базе сохраняются лаборатория, дата, источник даты, тип документа, исходное имя файла, внутренний путь и статус обработки.
12. Список и экран документа обновляются автоматически через Room `LiveData`.
13. Кнопка «Резервная копия» создаёт один зашифрованный файл через системное окно Android. Для восстановления нужен тот же пароль; потерянный пароль восстановить невозможно.
14. Опциональная защита приложения блокирует данные после ухода в фон и использует только системное окно Android — приложение не хранит отпечаток, лицо или PIN-код.
15. CSV-экспорт создаётся отдельно и не шифруется, поэтому перед сохранением приложение показывает предупреждение о конфиденциальности.

Приложение не запрашивает общий доступ ко всем файлам смартфона. Выбор производится системным механизмом Storage Access Framework.

## Как работает APK

APK — устанавливаемый пакет Android. В нём находятся скомпилированный Java-код, XML-интерфейс, ресурсы и манифест приложения.

После установки Android создаёт для пакета `ru.labhistory.app` отдельную изолированную область. База и загруженные документы не видны обычным файловым менеджерам и другим приложениям. При удалении приложения локальные данные также удаляются. Облачное резервное копирование базы и медицинских документов отключено; перенос выполняется только вручную через зашифрованный файл `.labbackup`.

В APK также находятся русская и английская модели Tesseract и модуль чтения PDF, поэтому обработка не требует загрузки моделей или доступа к интернету. Универсальный APK получается крупнее обычного — около 44 МБ.

Debug APK автоматически подписывается отладочным ключом компьютера и подходит для установки на свои устройства. Для публикации нужен release APK или Android App Bundle, подписанный постоянным приватным ключом владельца проекта.

## Обновления через GitHub

Release-версия проверяет публичный файл `update.json` из последнего GitHub Release. Если `versionCode` больше установленного, приложение показывает описание, загружает APK через системный DownloadManager, проверяет SHA-256 и передаёт файл системному установщику Android. Пользователь всегда подтверждает установку. Новая версия должна быть подписана тем же постоянным ключом.

Публикация запускается тегом, совпадающим с `versionName`, например:

```powershell
git tag v0.14.0
git push origin v0.14.0
```

Workflow `.github/workflows/release.yml` требует GitHub Secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS` и `ANDROID_KEY_PASSWORD`.

### Копия релиза на Яндекс Диске

После публикации GitHub Release workflow может автоматически скопировать APK, SHA-256 и `update.json` в папку приложения на Яндекс Диске: `Приложения/LabHistory/releases/<тег>/`. Медицинские документы и локальная база приложения в эту папку не отправляются.

Для подключения:

1. Создайте в [Яндекс OAuth](https://oauth.yandex.ru/client/new/) приложение типа «Для доступа к API или отладки».
2. Выдайте ему только право доступа к папке приложения на Яндекс Диске (`cloud_api:disk.app_folder`).
3. Получите OAuth-токен вручную для своего аккаунта.
4. В репозитории GitHub откройте **Settings → Secrets and variables → Actions → New repository secret**.
5. Создайте секрет с именем `YANDEX_DISK_TOKEN` и вставьте токен как его значение.

Токен нельзя добавлять в код, коммиты, логи или сообщения. Если секрет не настроен, GitHub Release продолжит публиковаться, а шаг копирования на Яндекс Диск будет безопасно пропущен.

## Сборка

Требования:

- Android Studio с Android SDK 36;
- JDK 17 или совместимая версия;
- подключение к интернету при первой синхронизации зависимостей.

В Android Studio откройте корень проекта, дождитесь Gradle Sync и выберите **Build → Build APK(s)**.

Из терминала Windows:

```powershell
.\gradlew.bat assembleDebug
```

Получившийся файл:

```text
app/build/outputs/apk/debug/app-debug.apk
```

Проверки и подписанная release-сборка:

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleRelease
```

Release APK:

```text
app/build/outputs/apk/release/app-release.apk
```

Установка через ADB:

```powershell
adb install -r app/build/outputs/apk/debug/app-debug.apk
```
