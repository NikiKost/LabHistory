# Архитектура LabHistory

## Слои

```text
UI (MainActivity)
       ↓
AnalysisRepository
       ↓
Room: Profile / AnalysisDocument / LabResult

URI из Android → DocumentImporter → приватный файл
                              ↓
                     будущий OCR/PDF extractor
                              ↓
             InvitroParser / Lab4uParser
                              ↓
                 экран проверки → Room
```

`ProfileEntity` представляет человека. `AnalysisDocumentEntity` представляет одну загрузку или сеанс ручного ввода. `LabResultEntity` представляет отдельный лабораторный показатель.

Оригинальный текст и единицы измерения должны сохраняться без потерь. Нормализованное числовое значение является дополнительным полем и не должно заменять исходное.

## Граница облака

Локальная версия не зависит от сервера. Будущий модуль синхронизации должен быть подключаемым репозиторием, а не заменой Room. Supabase сможет хранить синхронизированные записи и приватные файлы, а n8n — выполнять необязательные сценарии импорта из отдельного почтового ящика.

Секрет `service_role` никогда не должен попадать в APK. Доступ клиента к Supabase должен ограничиваться Row Level Security.

## Правило распознавания

Ни один распознанный показатель не считается подтверждённым автоматически. Перед записью пользователь должен увидеть исходный фрагмент, распознанное значение, единицу, референс и уровень уверенности.
